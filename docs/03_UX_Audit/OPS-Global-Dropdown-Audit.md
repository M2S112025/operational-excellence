# OPS Global Dropdown Audit

Date: 17 October 2026. Baseline: 918 tests / 108 files. This is an implementation inventory, not an authorization redesign.

## Counting and discovery

AST inventory covers app, components and features, native selects, Select, OpsPersonSelect, searchable controls, popovers and action menus. Imports and re-exports were followed from application routes. **92 reachable selection declaration sites**: 63 compositional Select sites, 28 OpsPersonSelect consumers and one native print-period select. A reusable filter factory counts once, even when it renders several fields or rows. These are source-site counts, not a claim of 92 distinct rendered fields. Both enabled and entitlement-gated live routes are included; entitlement gates are unchanged.

Additionally 5 reachable command-menu/information popover sites are catalogued below. 18 unreachable declarations are listed separately. Two shared selector implementation bodies are excluded from consumer counts. There was no Command/Combobox or multi-select dropdown implementation to retain. Role, permission and member checkbox groups are reviewed separately below.

## Implemented standard

Use the installed Base UI Combobox through OpsSearchableSelect. Person, Plant, Zone, Department, auditor/reviewer/member, Board, Organization, checklist, record, proposer, section, report generator and dynamic KPI selectors search even when their current list is short. Other lists search at **8 options**, including All/legacy entries. Short fixed choices remain Select; fixed Zone Responsibility and Metric Type are explicitly exempt from entity-word matching. Eight is a discoverability threshold, not a quantity or business limit.

Search is inside the portalled, trigger-width popup, focused on opening, case-insensitive, and matches label plus caller-permitted secondary description. Immediate results, selected indicator, no-results feedback, disabled options, keyboard navigation/Enter/Escape/Tab and mobile collision handling use Base UI. IDs remain values. Unavailable saved IDs remain displayed honestly; no automatic replacement. Clear is explicit and optional only. The component supports controlled/default values, required/name, helper/error/loading and optional group labels. No remote search, data fetching, new options, store or UI dependency was added.

**Rollout:** 29 explicit searchable conversions (28 person/entity consumers plus native Period); 30 additional Select factory/field sites use entity/long-list policy; 33 fixed-choice sites intentionally stay simple at current definitions. All 63 Select sites share the same policy implementation. Conditional factories can render both simple and searchable controls; they are not incorrectly counted as always searchable.

## Option authorization contract

Each row receives the exact original caller option array. The shared control cannot discover/fetch other users or Zones. Role/Plant/Zone restrictions remain at the caller, route and canonical command. Audit creation keeps canAuditZone/own-Zone disabled options and dependencies. Action assignment retains the selected Zone's members; CI retains selectableImprovementOwners; Red Tag retains zoneConfig.members; VM retains existing Board/configuration scope. Search is not server-side authorization. No policy was broadened.

## Multi-selection and intentional exceptions

- Users editor: four fixed role checkboxes and existing permission presets remain visible; no searchable dropdown would improve these few explicit choices. Stored role/permission codes and critical-admin safeguards are unchanged.
- Organization Zone editor: the searchable Members checkbox grid remains a multi-selection field. Its existing memberSearch filters the grid, not an adjacent dropdown. It retains active-user/leader exclusion and reassignment confirmation. It is intentionally not collapsed into a single-select or silently converted to new semantics.
- VM print size/content/category checkboxes remain explicit multi-selection/segmented choices; only the dynamic reporting Period native select was migrated.
- Report export and account/language action menus, notification popover and informational FieldInfo popover are command/information surfaces. They retain their accessible Menu/Popover behavior.
- Super Admin has no selection dropdown declaration in its current screen. Its cards/tabs/switches are not invented dropdowns; Organization selection on Module Access is searchable.
- Controlled popup/custom items APIs retain the existing Base UI Select fallback in the compatibility wrapper. No active consumer currently uses those unsupported combinations; do not claim the wrapper implements every future Select API.
- No native select remains in reachable application selection screens. The two native selectors in FiveSAuditChecklist are unreachable legacy code and were left intact.
