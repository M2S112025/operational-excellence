## Explicit exclusions / decisions

- Do not automate the imported 5S Red Tag planning/member/rework/closure system; restored OPS lifecycle is authoritative.
- VM Red Flag follow-up enum/legacy code is not an active new-record flow: entitlement forces Red Flag off and public new route is archived. VM escalation store compatibility can have unit characterization, but the current escalations URL redirects; no new active escalation UI acceptance journey is assumed.
- Walk and meeting completion do **not** globally require all linked Actions Completed. CI terminal approval, VI approval, Red Tag linked physical closure and legacy linked escalation resolution have their own restrictions. Audit completion validates ready questions/signature independently of Action closure.
- No universal reverse link for every entity is assumed. `getActionSourceHref` and `lib/relationships/route-resolver.ts` resolve some VM/legacy references with context/prefix heuristics; validate the actual supported destination and missing-record handling rather than inventing deep routes.
- Same browser local state can be tested by switching roles and reloading in one disposable context. Separate real users/devices have no shared backend synchronization. Cross-context tests must assert current isolation, not pretend remote updates propagate.
- Relationship metadata has no binaries/base64; underlying records own evidence. Tests must keep canonical Action IDs distinct from source IDs and must not infer links from display text when explicit fields exist.
