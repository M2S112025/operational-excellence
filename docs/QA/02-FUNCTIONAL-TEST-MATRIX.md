# Functional test execution matrix

These are planned execution specifications, not newly implemented tests. P0 protects data, authority, lifecycle and demo-critical access; P1 covers broader functional/media/export/compatibility behavior. Existing coverage identifies relevant file stems under `tests/`; it never implies browser coverage. A coverage row can require multiple parameterized checks. Every module/route surface in 01 must map to a row here plus responsive and route smoke.

“Desired denial” rows expose requirements beyond current implementation. Record current behavior separately; do not make an insecure behavior a passing acceptance criterion. No production/local user data may be used for fixtures. See isolation rules in 05.
